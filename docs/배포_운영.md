# 배포·운영 인수인계

평가 API 서버를 어떻게 올리고 무엇을 건드리면 안 되는지. **git 이 아니라 파일 복사로 배포한다.**

---

## 1. 서버 구조

```
주소      http://101.79.19.164          네이버클라우드 busanmans · Ubuntu 24.04
          c2-g3a · vCPU 2 · Memory 4GB · 스토리지 20GB
접속      ssh root@101.79.19.164        비밀번호는 NCP 콘솔
                                        → 서버 관리 및 설정 변경 → 관리자 비밀번호 확인
ACG      인바운드 22 · 80 · 443 · 3389 / 아웃바운드 전체
```

**앞단에 nginx 가 있다.**

```
GET /            → 프론트엔드 정적 파일        (팀원 mark77234 작업)
GET /answer      → 앱으로 프록시              평가용 엔드포인트
GET /health      → 앱으로 프록시              {"status":"ok","agent":"2호기"}
                   ★ HEAD 는 501 이다. 헬스체크를 HEAD 로 걸면 안 된다.
설정      /etc/nginx/sites-enabled/
```

**앱**

```
코드      /opt/gongsi                    ← git 저장소가 **아니다**. 파일 복사로 올라간다.
파이썬     /opt/gongsi/venv/bin/python    ← 시스템 python3 아니다
코퍼스     /data/corpus                   (CORPUS_DIR 환경변수로 넘어간다)
캐시      /opt/gongsi/agent2/.cache      정본표 · 정형공시 · PDF 표
비밀키     /opt/gongsi/agent2/.env        LLM_PROFILE=hcx 등. **저장소에 없다. 지우면 복구 불가.**
서비스     systemd `gongsi` · Restart=always · TimeoutStartSec=1800
```

`/etc/systemd/system/gongsi.service` 는 서버에만 있다. 핵심만:

```ini
WorkingDirectory=/opt/gongsi
Environment=CORPUS_DIR=/data/corpus
Environment=MALLOC_ARENA_MAX=2        # 4GB 에 파싱 피크 2.4GB — 지우지 마라
ExecStartPre=... -m agent2.data.filings   # records.jsonl 이 비었을 때만
ExecStart=/opt/gongsi/venv/bin/python -m agent2.server 80
```

수동 실행은 항상 이 꼴이다(환경변수가 셸에 상속되지 않는다):

```bash
cd /opt/gongsi && CORPUS_DIR=/data/corpus venv/bin/python -m agent2.warmup --check
```

## 2. ★★★ 절대 건드리면 안 되는 것

```
frontend/                팀원 mark77234 의 작업. 서버의 빌드 산출물과 저장소의 소스 둘 다.
/etc/nginx/              프론트를 서빙하는 설정.
/opt/gongsi/agent2/.env   자격증명. 저장소에 없어 복구할 곳이 없다.
/opt/gongsi/agent2/.cache 전처리 산출물. 지우면 재생성에 시간이 든다.
```

**그래서 `rsync -a --delete` 를 쓰지 않는다.** 위 넷이 통째로 날아간다.
배포는 **바꾼 파일만 이름을 적어** 보낸다.

## 3. 배포 절차

### ① 무엇이 바뀌는지 먼저 확인한다 — 서버는 git 이 아니라서 지문으로 본다

로컬(제출 저장소 체크아웃)에서 기대 지문을 뽑는다:

```bash
for f in agent2/tools/xbrl.py agent2/tools/finance.py; do
  printf "%-28s %s\n" "$f" "$(shasum -a 256 $f | cut -c1-16)"
done
```

서버에서 현재 지문을 뽑아 대조한다:

```bash
ssh root@101.79.19.164 'cd /opt/gongsi && for f in agent2/tools/xbrl.py agent2/tools/finance.py; do
  printf "%-28s %s\n" "$f" "$(sha256sum $f | cut -c1-16)"; done'
```

**바꿀 파일만 다르고 나머지는 같아야 한다.** 다르면 멈추고 왜 다른지 먼저 본다
(서버 코드가 저장소와 갈라져 있을 수 있다 — 실제로 그런 적이 있다).

### ② 백업

```bash
ssh root@101.79.19.164 'B=/opt/gongsi/_bak_$(date +%m%d_%H%M); mkdir -p $B/{data,tools}
  cd /opt/gongsi/agent2
  cp tools/{xbrl,finance,__init__,claims}.py $B/tools/ ; cp ../loop.py $B/
  echo "백업 → $B"'
```

### ③ 파일 지정 전송 (`--delete` 없음)

```bash
scp agent2/tools/xbrl.py   root@101.79.19.164:/opt/gongsi/agent2/tools/xbrl.py
scp agent2/tools/finance.py root@101.79.19.164:/opt/gongsi/agent2/tools/finance.py
# … 바꾼 파일만
```

rsync 를 쓰려면 반드시 파일을 열거하고 `--delete` 를 빼라:

```bash
rsync -av agent2/tools/xbrl.py agent2/tools/finance.py \
      root@101.79.19.164:/opt/gongsi/agent2/tools/
```

### ④ ★ 캐시를 다시 만들어야 하나

```
agent2/tools/doctables.py  또는  agent2/data/parse.py 를 바꿨나?
   예  → `_code_version()` 해시가 갈려 .cache/canon_tables 전체가 무효다. 재예열 필수.
        cd /opt/gongsi && CORPUS_DIR=/data/corpus venv/bin/python -m agent2.warmup
   아니오 → 캐시는 그대로 유효하다. 아무것도 안 해도 된다.
```

### ⑤ 재시작과 검증

```bash
ssh root@101.79.19.164 '
  cd /opt/gongsi
  for f in agent2/tools/xbrl.py agent2/tools/finance.py; do
    printf "%-28s %s\n" "$f" "$(sha256sum $f | cut -c1-16)"; done   # 지문이 기대값인가
  ls -l agent2/.env && grep -c LLM_PROFILE agent2/.env              # .env 살아있나
  systemctl restart gongsi && sleep 8 && systemctl is-active gongsi
  journalctl -u gongsi -n 60 --no-pager | grep -iE "LLM:|Traceback"
'
```

기동 로그에 **`LLM: hcx / HCX-005 — 실호출 가능`** 이 보여야 한다.
안 보이면 `.env` 가 없거나 프로필이 다른 것이고, **다른 모델로 서빙하면 규정 위반이다.**

```bash
curl -s http://101.79.19.164/health
curl -s http://101.79.19.164/          # 프론트가 살아 있나 (mark77234 작업)
curl -sG "http://101.79.19.164/answer" \
  --data-urlencode "question_id=SMOKE" \
  --data-urlencode "question=네이버의 2025년 3분기 당기순이익은 얼마야?"
```

★ 질의 한 번에 CLOVA 크레딧이 약 15~20원 나간다. 테스트는 몇 번만.

## 4. GitHub 에 올릴 때 — 팀원 작업을 지키는 규칙

```
① fast-forward 만 한다. `--force` 절대 금지.
   fast-forward 는 기존 커밋을 수정할 수 없으므로 남의 커밋을 구조적으로 못 건드린다.
② 푸시 전후로 frontend 트리 해시를 대조한다:
     git rev-parse <이전커밋>:frontend
     git rev-parse origin/main:frontend      ← 같아야 한다
③ 커밋 전에 `git status` 로 `agent2/` 밖 파일이 스테이징되지 않았는지 본다.
④ 푸시 직전에 `git fetch` 를 다시 해서 그 사이 올라온 커밋 위에 얹는다.
```

## 5. 운영 중 점검

```
Restart=always 라 프로세스가 죽으면 알아서 살아난다.
free -h                              메모리 여유 (앱 상주 2.0GB · 파싱 피크 2.4GB · 스왑 4GB)
dmesg | grep -i "out of memory"      OOM 있었나
systemctl restart gongsi             재기동
```

메모리가 모자라면 `agent2/tools/doctables.py` 의 `lru_cache(maxsize=64)` 를 낮춘다
(16이면 상주 931MB 로 내려간다 — 실측). **코드 변경이라 마감 전에만 가능하다.**

★ 장애 대응 재기동은 결과물 변경이 아니므로 실격이 아니다(주최 확인).
